## 👨‍🏫 TEACHING MOMENT

### This Week I Learned:

**Topic:** Hash Table Patterns - The Power of Pattern Recognition

**Explanation:**

This week I discovered that hash tables aren't just one technique - they're actually FIVE distinct patterns, each solving different types of problems. The key insight is that the VALUE you store determines what pattern you're using.

**COUNTING pattern** (value = count) answers "how many times?" - perfect for frequency problems like finding the most common element or counting character occurrences.

**SEEN pattern** (value = True/False) answers "have I seen this?" - ideal for detecting duplicates or checking if a complement exists, like in the two-sum problem.

**POSITION pattern** (value = index) answers "where is this?" - essential for problems needing to track locations, like finding the first unique character or implementing sliding windows.

The breakthrough was realizing that by recognizing which QUESTION you're trying to answer, you immediately know which pattern to use. It's like having a mental checklist: "Do I need to count? Just check existence? Or track position?" This pattern recognition makes solving hash table problems much faster and more intuitive.

**Visual Aid:**
```
Problem: "Find duplicate" → Question: "Have I seen this?" → Pattern: SEEN
Problem: "Most frequent" → Question: "How many times?" → Pattern: COUNTING  
Problem: "Two sum indices" → Question: "Where is complement?" → Pattern: POSITION
```

**Why This Matters:**
- Transforms hash tables from confusing to systematic
- Pattern recognition speeds up problem-solving
- Same approach works across many problems
- Foundation for more advanced techniques (sliding window)
- Builds intuition for when to use hash tables vs other structures
