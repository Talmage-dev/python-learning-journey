# Retention-Focused Learning Strategy

## Date Created: October 23, 2025

---

## The Problem

Learning new concepts quickly but struggling with:
- **Recall** - Writing methods from memory
- **Speed** - Slow to implement structures
- **Application** - Knowing when/how to use each structure

---

## The Solution: Depth + Repetition

Focus on **retention and application** rather than just coverage.

---

## Daily Routine

### Morning (15 minutes)
**Typing Practice**
- Keybr.com - 15 minutes
- Track WPM and accuracy

### Learning Session (2-4 hours)
**Four-Step Process:**
1. Learn the Material (theory, concepts)
2. See It In Action (examples)
3. "Wax On Wax Off" (practice from memory)
4. Apply with Projects (build something)

### End of Day (10-15 minutes)
**Mini "Wax On Wax Off"**
- 5-7 random methods from **last 3 days** of topics
- Quick retention check
- Builds recall speed

---

## Weekly Routine

### End of Week (30 minutes)
**Comprehensive "Wax On Wax Off"**
- ALL methods from ALL topics learned that week
- 2 consecutive correct per method to master
- Builds long-term retention

### Application Practice (2-3 times per week)
**Structure Selection Challenges:**
- Given a problem, choose the right structure
- Build small projects requiring decision-making
- Examples:
  - "Build an undo system" → Stack
  - "Build a print queue" → Queue
  - "Build a sorted collection" → BST

---

## Learning Pace

### New Topics
**One major topic per week** (not per day!)

**Example:**
- Week 1: Trees (learn + practice + apply)
- Week 2: Hash Tables (learn + practice + apply)
- Week 3: Graphs (learn + practice + apply)

### Daily Focus
- **Day 1-2:** Learn new topic
- **Day 3-4:** Practice + small projects
- **Day 5-6:** Application project
- **Day 7:** Comprehensive review

---

## Practice Schedule

### Daily Mini Review (10-15 min)
**Last 3 Days of Topics**

Example for Day 17:
- 1 method from Stack
- 1 method from Queue
- 1 method from LinkedList
- 1 method from Tree
- 1 method from any structure

**Goal:** Build speed and recall

### Weekly Comprehensive Review (30 min)
**All Topics from Current Week**

Example for Week 3:
- All Stack methods (2x each)
- All Queue methods (2x each)
- All LinkedList methods (2x each)
- All Tree methods (2x each)

**Goal:** Long-term retention

---

## Project Types

### Small Projects (1-2 hours)
**Purpose:** Practice using ONE structure
- Stack: Undo system, bracket matcher
- Queue: Task scheduler, print queue
- LinkedList: Playlist, browser history
- Tree: Sorted collection, file system

### Medium Projects (3-4 hours)
**Purpose:** Combine 2-3 structures
- Task Manager (Queue + Stack + LinkedList)
- Priority System (Tree + Queue + Stack)

### Large Projects (1-2 days)
**Purpose:** Comprehensive application
- Complete system using multiple structures
- Real-world problem solving
- Portfolio-worthy

---

## Retention Techniques

### 1. Spaced Repetition
- Daily mini reviews (last 3 days)
- Weekly comprehensive reviews (all topics)
- Monthly mega reviews (all previous weeks)

### 2. Active Recall
- Write from memory (no looking!)
- "Wax On Wax Off" method
- Random order exercises

### 3. Application Practice
- Build projects requiring structure selection
- Solve problems with constraints
- Explain choices out loud

### 4. Pattern Recognition
- Identify common patterns across structures
- Understand when to use each
- Build mental models

## Weekly Template

### Monday
- Learn new topic (theory + examples)
- Initial "Wax On Wax Off"
- Daily mini review (last 3 days)

### Tuesday
- Continue new topic
- Practice exercises
- Daily mini review

### Wednesday
- Small project using new topic
- Daily mini review

### Thursday
- Medium project (combine structures)
- Daily mini review

### Friday
- Continue project or start new one
- Daily mini review

### Saturday
- Application project
- Daily mini review

### Sunday
- **Comprehensive weekly review**
- Rest and reflect
- Plan next week

---

## Success Metrics

### Speed
- Can write basic methods in < 2 minutes
- Can implement structure from scratch in < 10 minutes

### Accuracy
- Methods work correctly first try
- No syntax errors
- Proper edge case handling

### Application
- Can choose correct structure for problem
- Can explain why structure is appropriate
- Can combine structures effectively

---

## Adjustments

### If Retention is Still Low:
- Increase daily mini review to 20 minutes
- Add mid-week comprehensive review
- Slow down new topic introduction

### If Retention is Good:
- Reduce daily mini review to 10 minutes
- Add more application projects
- Increase pace slightly

### If Application is Weak:
- More structure selection challenges
- Build projects with constraints
- Practice explaining choices

## Key Principles

1. **Quality over Speed** - Deep understanding beats surface coverage
2. **Repetition is Key** - Practice makes permanent
3. **Application Matters** - Use it or lose it
4. **Spaced Practice** - Daily + weekly reviews
5. **Active Recall** - Write from memory
6. **Real Projects** - Build to learn

---

## Notes

- This strategy prioritizes **retention and application** over speed
- Still finishes Phase 1 on time (or early!)
- Builds **deeper understanding** and **practical skills**
- Prepares for **real-world programming** not just passing tests
